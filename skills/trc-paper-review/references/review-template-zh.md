# TR-C 模拟审稿报告

## 0. 论文概要

用 3–5 句话说明：研究什么交通问题、提出什么方法、在什么数据/网络上验证、主要结果、声称的贡献。

**论文元数据**：题目 / 类型（方法型、实证型、仿真型、实地实验型、综述、数据论文）/ 子领域 / 目标期刊（默认 TR-C）。

## 0.5 校准基准（仅在用户上传范例论文时输出）

列出所用范例论文、提取的各维度标杆（证据深度、实验规模、基线、指标、可复现性），以及被审稿论文与标杆的逐项差距。未上传范例时注明"本次校准使用内置 TR-C 标准档案"。

## 1. 范围契合与题目/摘要/正文一致性检查

### 1.1 交通系统后果检验（TR-C 核心编辑标准）
- 论文的知识核心在交通侧还是技术侧？给出判定和证据。
- 报告了哪些系统级指标（延误、通行能力、可靠性、安全、能耗、排放、服务质量）？还是只有算法指标？
- 若判定为"技术演示缺乏交通系统后果"，明确给出转向建议（TR-B / T-ITS / CS 会议等）。

### 1.2 题目承诺
列出题目暗示或承诺的贡献。

### 1.3 摘要声明
逐条列出摘要中的技术与实验声明。

### 1.4 正文支撑度
逐条判断正文证据是否支撑摘要声明（支撑 / 部分支撑 / 不支撑 + 定位）。

### 1.5 不匹配点
列出所有 overclaim 与不一致（如：声称 general 但只测单一路口；声称 real-time 但无运行时间报告；声称 outperform SOTA 但基线过时）。

每条格式：**[位置] 问题描述 → 对结论的影响 → 建议如何修复**。

## 9. 最终直接回答

1. 这篇论文现在能不能投 TR-C？
2. 现在投，最大的拒稿风险是什么？
3. 最可能被哪位 reviewer 打低分、因为什么？
4. 最应该补哪一组实验？
5. 最应该重写哪一节？
6. 当前版本的分数组合更像什么（如 445 / 556 / 667）？
7. 认真修改一轮后，最现实的分数组合？
8. 是否建议转投其他期刊（TR-B / TRR / T-ITS / ITSC 等）？给出匹配理由。
9. 若是大修，response letter 中最需要策略性回应的三点是什么？

要求：严格、直接、具体。不安慰作者，不泛泛而谈。所有判断服务于一个问题——这篇论文是否达到了 TR-C 的发表标准。
